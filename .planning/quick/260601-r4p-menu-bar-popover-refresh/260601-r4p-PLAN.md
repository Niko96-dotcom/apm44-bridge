# Quick Task 260601-r4p: Menu bar popover visual refresh

## Goal

Make the APM44 Bridge menu bar popover look polished and intentional instead of
cramped/utilitarian. View layer only — no changes to `BridgeProcessManager`,
`BridgeSettings`, or daemon behavior. Direction chosen by user: **fuller visual
refresh** (not just targeted bug fixes).

## Problems being fixed

1. **Latency segmented control overflows** — three long labels
   (`Low (~8 ms)` / `Balanced (~15 ms)` / `Safe (~30 ms)`) clip inside the 320pt
   window. → Short segment labels (`Low`/`Balanced`/`Safe`) + dynamic target
   detail line beneath.
2. **"Monitoring adds latency" rendered as a `.title3` heading** — reads as an
   alarming section title when idle. → Demote to a footnote-weight info row WITH
   icon. Keep the honesty message (project forbids "zero latency" copy — see
   `scripts/verify-menu-bar.sh`).
3. **Weak hierarchy / mixed controls** — segmented + two inline `.menu` pickers,
   all left-aligned, cramped. → Status "hero" up top, grouped control card,
   consistent labeled rows with leading SF Symbols.
4. **Empty Output picker** when nothing selected. → Add a "Choose output…"
   placeholder row.
5. **No distinct idle vs running layout.** → Hero shows live latency badge +
   metrics when running; Start hint + controls when idle.

## Tasks

- **Verify:** `rg "return 8|return 15|return 30" LatencyPreset.swift` still passes.
