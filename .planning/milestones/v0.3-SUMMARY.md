# v0.3 Milestone Summary — Realtime Audio Hardening

## One-line summary

v0.3 closes the realtime correctness risks identified at the end of v0.2 by
enforcing SPSC ownership in the audio callbacks, fixing stop/restart races
under concurrent waiters, publishing metrics through a race-free mechanism,
and rejecting malformed HAL shared-memory objects before trusting their
declared layout.

## What shipped (by phase)

### Phase 9 — Realtime Callback Ownership (RT-01..05)

- **RT-01 / RT-02**: input overrun policy is now "drop unaccepted new input"
  in the producer. `BridgeInputOverrun::DropOldestThenPush` no longer calls
  `PlanarRingBuffer::pop()`; it returns the unaccepted tail count and the
  drift controller is notified.
- **RT-03 / RT-04**: oversized interleaved and non-interleaved output
  callbacks now explicitly silence the tail `[framesToRender, requestedFrames)`
  after writing the rendered portion. No stale samples in the Core Audio
  output buffer.
- **RT-05**: `tests/test_io_proc_callbacks.cpp` and updated
  `tests/test_planar_ring_buffer.cpp` cover the new policy without touching
  `/apm44_bridge_ring`.

### Phase 10 — Process and Metrics Race Hardening (PROC-01..04, METR-01..03)

- **PROC-01..03**: `BridgeProcessManager` tracks termination waiters in a
  `terminationContinuations: [CheckedContinuation<...>]` list. Concurrent
  callers all complete; none overwrites another. The
  `testConcurrentTerminationWaitersAllComplete` test exercises this.
- **PROC-04**: Swift `test_bridge_process_manager.swift` covers the
  timeout / escalation / concurrent-waiter / settings-restart / hotplug
  paths.
- **METR-01..03**: `MetricsPublisher` is a standalone type with a
  `std::atomic<uint32_t>` seqlock and a `MetricsSnapshot` payload.
  `MetricsSnapshot` was extracted to `Shared/include/apm44/MetricsSnapshot.h`
  to break the cycle. A multi-threaded stress test
  (`MetricsPublisherSeqlockNeverDeliversTornSnapshot`) and a source-level
  guard (`NoBareMetricsSnapshotCopyInSource`) prove the race-free contract.

### Phase 11 — Shared-Memory Validation Hardening (SHM-01..05)

- **SHM-01**: `MmapShmRing::open()` rejects objects smaller than
  `sizeof(ShmRingHeader)` *before* mapping or dereferencing the header, with
  the new `HeaderTruncated` error code.
- **SHM-02**: after `ValidateShmHeader` passes, `open()` checks that the
  mapped size can hold `ShmTotalSize(capacity_frames)`. The new
  `CapacityExceedsObject` error code fires otherwise.
- **SHM-03**: `ShmObjectIdentity` now carries a `size` field.
  `CaptureMappedIdentity` stores `st.st_size`. `isMappedObjectStale()` and
  `ShmObjectIdentityChanged` compare it against the current `st.st_size`.
- **SHM-04**: `DescribeHeaderMismatch` renders build IDs through a bounded
  `RenderBoundedBuildId` helper that uses `strnlen` and substitutes
  `<unterminated>` for empty fields.
- **SHM-05**: new `tests/test_mmap_shm_validation.cpp` with 5 functional
  test cases and 2 source-level guards (SHM-01 and SHM-03 functional
  coverage is not possible on macOS due to shm page-rounding; the
  source-level guards assert the same invariants).

### Phase 12 — Verification Closure (QA-01..05)

- **QA-01 / QA-02**: `scripts/ci.sh` now invokes
  `bash scripts/verify-installed-sync.sh --dry-run` after the Swift unit
  tests. The full `bash scripts/ci.sh` gate goes green; the first run
  caught a real build-ID drift between the repo daemon and the embedded
  helper.
- **QA-03 / QA-04**: live installed-system proof and operator evidence are
  hardware-blocked on this dev machine. The dev-environment CI proof is
  sufficient for the milestone archive (matching the v0.2 archive
  precedent). The four blocked items are recorded in
  `12-LIVE-VERIFICATION.md` with exact unblock commands.
- **QA-05**: the milestone close records the hardware-only caveats in
  `STATE.md`'s Deferred Items and in the milestone audit.
