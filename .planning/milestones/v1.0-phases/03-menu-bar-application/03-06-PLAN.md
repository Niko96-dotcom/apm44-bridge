## Phase Goal

**As a** producer using APM44 Bridge, **I want** the bridge to survive AirPods connect/disconnect, **so that** I can put headphones on/off without restarting my DAW session.

<objective>
Add **Core Audio hotplug listener** on background queue with **1 s debounce**; if bridge was running, stop and start with same settings (CONTEXT).

Purpose: APP-04.
Output: `HotplugMonitor` integrated at app launch.
</objective>

<task type="auto">
  <name>Task 1: HotplugMonitor Core Audio listener</name>
  <files>App/APM44Bridge/HotplugMonitor.swift</files>
  <action>
Create `HotplugMonitor` (Objective-C bridge **not** required — use Swift `AudioObjectAddPropertyListener` via small C shim file `HotplugMonitorShim.c` + bridging header **only if** Swift cannot link CoreAudio listeners cleanly; prefer pure Swift with `import CoreAudio`).

Listen for `kAudioHardwarePropertyDevices` on `kAudioObjectSystemObject` **or** `kAudioDevicePropertyDeviceIsAlive` on the selected output `AudioDeviceID` resolved from UID via `AudioObjectGetPropertyData`.

On fire:
- Schedule debounced work item **1.0 s** on `DispatchQueue.global(qos: .utility)`; cancel prior pending work (debounce).
- Callback to `@MainActor` `BridgeProcessManager.handleHotplug()`.

**No audio I/O in listener** — enqueue only.

Register on init; remove listener on deinit.
  </action>
  <verify>
    <automated>bash scripts/verify-app-build.sh</automated>
  </verify>
  <done>Project builds with HotplugMonitor; listener registers without crashing on launch.</done>
</task>

<task type="auto">
  <name>Task 2: Restart policy and device re-resolve</name>
  <files>App/APM44Bridge/BridgeProcessManager.swift, App/APM44Bridge/APM44BridgeApp.swift, App/APM44Bridge/MenuContentView.swift</files>
  <action>
`BridgeProcessManager.handleHotplug()`:
1. If state != `.running`, return.
2. `DeviceCatalog.refresh` — if selected UID missing, set `error("Output device disconnected")`, `stop()`, show Refresh hint; **do not** spin restart loop.
3. If UID still present or reappeared: `stop()` → brief 200 ms sleep (discretion) → `start()` with same `BridgeSettings`.

Optional menu footnote: "Auto-restart on device change" (enabled always this phase).

Wire `HotplugMonitor` lifetime in `APM44BridgeApp` `.onAppear` with `BridgeProcessManager` + `BridgeSettings` injected.

**Per CONTEXT:** restart only if was running; debounce 1 s at monitor layer.

**Out of scope:** changing DAW device list (deferred HAL phase).
