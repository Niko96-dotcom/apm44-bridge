  <name>Task 1: DeviceEnumerator — list, match, fail-fast</name>
  <files>BridgeDaemon/src/hal/HalTypes.h, BridgeDaemon/src/hal/DeviceEnumerator.h, BridgeDaemon/src/hal/DeviceEnumerator.cpp, tests/test_device_enumerator.cpp</files>
  <behavior>
    - Test: `MatchBlackHoleDefault` returns device when mock list contains name "BlackHole 2ch".
    - Test: `MatchAirPodsDefault` prefers name containing "AirPods Max" over generic "AirPods".
    - Test: Missing BlackHole yields error code/message containing "BlackHole".
  </behavior>
  <action>
Implement `DeviceEnumerator` using `AudioObjectGetPropertyData` on `kAudioHardwarePropertyDevices` and per-device `kAudioDevicePropertyDeviceUID`, `kAudioObjectPropertyName`, `kAudioDevicePropertyNominalSampleRate`.

Structs: `AudioDeviceInfo { std::string uid; std::string name; double nominalRate; bool isInput; bool isOutput; }`.

Methods:
- `std::vector<AudioDeviceInfo> listAll()`
- `std::optional<AudioDeviceInfo> findByUid(std::string_view uid)`
- `std::optional<AudioDeviceInfo> defaultInput()` — name contains `BlackHole`, ≥2ch if channel info available
- `std::optional<AudioDeviceInfo> defaultOutput()` — name contains `AirPods Max` (fallback `AirPods` + USB in description if available)

**Per CONTEXT:** Do NOT call `AudioObjectSetPropertyData` on `kAudioDevicePropertyNominalSampleRate` for AirPods to force 44100 — verify only.

Extract matching logic to pure functions testable without HAL where possible (inject device list in tests).

Wire `main.cpp`: add `--list-devices` (print table UID | name | rate | I/O); add `--preflight` that resolves defaults/overrides and exits 0 only when devices exist with correct nominal rates (44100 in, 48000 out).
  </action>
  <verify>
    <automated>cmake --build build && ctest --test-dir build -R device_enumerator --output-on-failure && ./build/BridgeDaemon/apm44-bridge --list-devices 2>/dev/null | grep -ci blackhole || true</automated>
  </verify>
  <done>Enumerator lists devices; defaults match CONTEXT heuristics; preflight fails with clear stderr if BlackHole missing or rates wrong.</done>
</task>

`FormatNegotiator`:
- For a resolved `AudioDeviceID`, read output/input stream `kAudioDevicePropertyStreamFormat` for the appropriate scope.
- Verify ASBD matches `MakeFloat32StereoNonInterleaved` at expected rate (44100 input, 48000 output) within tolerance; if mismatch, return structured error telling user to set rate in Audio MIDI Setup (do not attempt rate change on AirPods per D-03 / PITFALLS).

Store negotiated `AudioStreamBasicDescription` in a `BridgeDevicePair` struct for Plan 01-03.

- Use `system_profiler SPAudioDataType` to grep for BlackHole and AirPods entries.
- Print PASS/FAIL lines for "BlackHole nominal 44100" and "AirPods nominal 48000".
- Optional: if `SwitchAudioSource` in PATH, list devices; document optional `brew install switchaudio-osx` in comment header — do not require it.

Integrate preflight: after negotiation, log chosen UID/name/rate to stderr (main thread only).
  </action>
