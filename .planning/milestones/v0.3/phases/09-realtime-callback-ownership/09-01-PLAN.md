# Plan 09-01: Producer-side overrun policy and SPSC tests

## Objective

Remove the producer-side `ring.pop()` call in `BridgeInputOverrun.h` so the
input path no longer crosses the SPSC ownership boundary, surface overruns
to `DriftController` via `push`'s return value, and lock the new policy in
with Catch2 tests that exercise a non-production `PlanarRingBuffer` instance
(RT-01, RT-02, RT-05).

## Tasks

### Task 1: Rewrite `BridgeInputOverrun.h` to drop input on overrun, not pop

**Type:** auto
**Files:** `BridgeDaemon/src/engine/BridgeInputOverrun.h`

Replace the entire body of `DropOldestThenPush` so it:

1. Calls `ring.push(channels, frames)` exactly once.
2. If the returned accepted-frame count is less than `frames`, calls
   `drift.notifyOverrun()` and returns the accepted count (the caller
   already uses the count to decide what to do with the residual input).
3. Never calls `ring.pop()` from the producer path.

Keep the function signature stable — the caller in `BridgeEngine.cpp` already
uses it from the input realtime path and must not be churned by an API
change.

Document the chosen policy in a header comment: "Input overrun handling
drops the unaccepted tail of the incoming block and notifies the drift
controller. The output consumer is the only path that may pop frames from
the ring (see `VirtualDeviceFeed`)."

### Task 2: Add Catch2 cases covering the producer-side policy

**Type:** auto
**Files:** `tests/test_planar_ring_buffer.cpp`, `tests/CMakeLists.txt`

Add three new `TEST_CASE`s in `test_planar_ring_buffer.cpp` (the file
already covers the buffer's SPSC API):

1. **`ProducerPushIntoFullRingDoesNotPop`** — prepare a `PlanarRingBuffer`
   with capacity N, fill it, then attempt to push M more frames. Assert:
   `push` returns 0 (or less than M), no call to `pop` is made (the test
   only constructs the ring and calls `push` — proving the producer path
   does not need a `pop`), and `availableToRead()` still equals N
   (unchanged). Use a small lambda that calls `push` and records the
   return value; do not invoke `pop` from this test.
2. **`ProducerPushShortReturnTriggersOverrunNotification`** — same setup,
   but wrap a `DriftController` and assert `drift.overrunCount()` is
   incremented exactly once when the producer reports a short push.
3. **`ProducerPathIsolatedFromConsumerState`** — fill the ring from the
   "producer" side, then drive the "consumer" `pop` path. Assert that
   interleaving the two paths is safe (no UB, no out-of-range data). This
   test exists to document the SPSC contract and would fail loudly if a
   future refactor reintroduced producer-side `pop` (the new test will
   fail to compile if `pop` is removed, signalling the contract change).

Wire the new test file into `tests/CMakeLists.txt` if it isn't already.

All tests use a stack-allocated `PlanarRingBuffer` — no shared memory, no
`/apm44_bridge_ring` (RT-05).
