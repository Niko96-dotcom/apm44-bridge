# Plan 09-02: Oversized output callback safety

## Objective

Make the interleaved and non-interleaved Core Audio output callbacks safe
when Core Audio supplies a frame count larger than the internal scratch
buffer capacity: every actual frame must be either rendered with valid
samples or explicitly silenced — no stale tail samples, no incorrect byte
counts (RT-03, RT-04, RT-05).

## Tasks

### Task 1: Audit the current oversized-callback behaviour

**Type:** auto
**Files:** `BridgeDaemon/src/engine/VirtualDeviceFeed.cpp`,
`BridgeDaemon/src/engine/VirtualDeviceFeed.h`

Read the two output callback entry points (interleaved and non-interleaved)
and the helper that renders from the planar ring into Core Audio's buffer.
For each, identify:

- Where the scratch capacity is checked.
- What happens when `ioData->mNumberFrames` (or the non-interleaved
  `mBuffers[p].mDataByteSize` equivalent) exceeds the scratch capacity.
- Whether the tail beyond the scratch is left untouched (stale samples)
  or zeroed.
- Whether the function writes the wrong `mDataByteSize` when it
  short-copies.

This is a read-only audit — record findings in a header comment in
`VirtualDeviceFeed.cpp` next to the relevant function so the executor
that ships the fix has a clear baseline.

### Task 2: Fix interleaved output path for oversized callbacks

**Type:** auto
**Files:** `BridgeDaemon/src/engine/VirtualDeviceFeed.cpp`

For the interleaved output callback:

1. Read `ioData->mNumberFrames` into a local `frameCount` variable.
2. Determine `framesToRender = min(frameCount, scratchCapacityFrames)`.
3. Render into the scratch buffer for `framesToRender` frames.
4. For frames `[framesToRender, frameCount)`, write `0.0f` directly into
   `((float*)ioData->mBuffers[0].mData) + i`.
5. Do not mutate `mDataByteSize` — Core Audio set it for the full
   `frameCount`, and we are writing all of it (silenced where needed).
6. If `frameCount == 0` or `ioData->mBuffers[0].mData == nullptr`, return
   early (already the case in most Core Audio adapters — keep the
   guard).

This satisfies RT-03 and the "no stale tail" half of RT-04.

### Task 3: Fix non-interleaved output path for oversized callbacks

**Type:** auto
**Files:** `BridgeDaemon/src/engine/VirtualDeviceFeed.cpp`

Mirror the interleaved fix for the non-interleaved path:

1. For each channel buffer `mBuffers[p]` (p = 0..channelCount-1), compute
   `framesAvailable = mDataByteSize / sizeof(float)`.
2. Render `min(framesAvailable, scratchCapacityFrames)` frames per channel.
3. Silence the tail `[framesRendered, framesAvailable)` with explicit
   zero writes.
4. Do not change `mDataByteSize` — Core Audio owns it.

This satisfies RT-04.

### Task 4: Add Catch2 test for oversized output callbacks

**Type:** auto
**Files:** `tests/test_virtual_device_feed.cpp`, `tests/CMakeLists.txt`

Add a new test file `test_virtual_device_feed.cpp` (or extend the
existing one) with a `TEST_CASE` named
**`OversizedInterleavedOutputSilencesTail`**:

1. Construct the output helper directly (not through Core Audio) with a
   scratch capacity of 64 frames.
2. Build a fake interleaved `AudioBufferList` with `mNumberFrames = 256`
   (4× scratch). Allocate a zero-initialized `float` buffer of 256
   samples and wire it as `mBuffers[0].mData`.
3. Call the output render function.
4. Assert: the first 64 samples are non-zero (rendered) or zero, but
   samples 64..255 are **explicitly zero** (proves no stale tail).
5. Assert: `mDataByteSize` was not modified (256 * sizeof(float)).

Add a second case **`OversizedNonInterleavedOutputSilencesTail`** for the
non-interleaved path that checks each channel's tail was zeroed.

These tests must not touch `/apm44_bridge_ring` (RT-05). They instantiate
the output helper with a local `PlanarRingBuffer` or a stub render source.

Wire the new test file into `tests/CMakeLists.txt`.

### Task 5: Build and run tests

**Type:** auto
**Files:** (none modified)

Run the project build and Catch2 test target. Confirm all tests pass —
both the producer-side tests from 09-01 and the new oversized output
tests. Capture the test output in the commit message.

## Success Criteria

- `grep -n "mDataByteSize\s*=" BridgeDaemon/src/engine/VirtualDeviceFeed.cpp`
  shows no mutation of the field in the output paths.
- Both interleaved and non-interleaved paths have a "silence the tail"
  branch when `frameCount > scratchCapacity`.
- The new oversized-callback test cases run and pass.
- No `/apm44_bridge_ring` reference in the test files.
