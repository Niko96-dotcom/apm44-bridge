# Plan 12-02: Live installed-system evidence and operator checklist

## Objective

Capture the live installed-system evidence we *can* capture on a
non-hardware dev machine (repo daemon build ID, embedded helper
build ID, app bundle build ID, dry-run shm status), and record
the explicit hardware-only blocker sections for the parts that
need a real USB-C AirPods pair and an installed HAL driver.
Produce `12-LIVE-VERIFICATION.md` as the operator evidence
record (QA-03, QA-04, QA-05).

## Tasks

### Task 1: Run the hardware-independent live evidence commands

**Type:** auto
**Files:** (none modified)

Run each of the following and capture stdout + exit code:

1. `bash scripts/verify-installed-sync.sh --dry-run` — must
   exit 0 with `OK: repo ID only` or with the helper ID match.
2. `build/BridgeDaemon/apm44-bridge --version` — capture the
   `build=` value. This is the repo daemon build ID.
3. `bash scripts/embed-daemon-in-app.sh` (idempotent re-embed)
   — must run cleanly.
4. `App/APM44 Bridge.app/Contents/MacOS/apm44-bridge --version`
   — capture the embedded helper build ID and confirm it
   matches the repo daemon ID.
5. `build/BridgeDaemon/apm44-bridge --shm-status` — capture the
   output. If the bridge is not running and the shm object is
   absent, that is an expected `WARN: --shm-status produced no
   output` result, not a failure.

Save each command and its output to
`12-LIVE-VERIFICATION.md` under the matching subsection.

### Task 2: Run `verify-hal-driver.sh` if a HAL driver is installed

**Type:** auto
**Files:** (none modified)

If a HAL driver is installed on the dev machine, run
`bash scripts/verify-hal-driver.sh` and capture the output. If
no HAL driver is installed, record the exact pre-requisite
(`scripts/install-driver.sh` was not run; no `/Library/Audio/Plug-Ins/HAL/apm44bridge.driver`
present) and skip.

### Task 3: Document the operator-only QA-04 evidence checklist

**Type:** auto
**Files:** `.planning/phases/12-verification-closure/12-LIVE-VERIFICATION.md`

Add a `## QA-04 Operator evidence checklist` section listing,
for each operator command, the exact invocation, the expected
output, and the hardware prerequisite. The checklist must cover:

- `verify-hal-driver.sh` (HAL driver installed).
- `--shm-status` while bridge is running (active HAL ring).
- USB-C AirPods hotplug smoke (real AirPods pair).
- Cubase HAL smoke (Cubase running with 44.1 kHz project).
- Cubase HAL soak (multi-minute, recorded xruns/recoveries).

Each item must be either:

- `[x]` — captured in this milestone (only items from Task 1
  and Task 2 can be ticked here), or
- `[ ] BLOCKED:` — with the exact blocker and the operator
  step required to unblock.

### Task 4: Write the QA-05 hardware-only caveat

**Type:** auto
**Files:** `.planning/phases/12-verification-closure/12-LIVE-VERIFICATION.md`

Add a final `## QA-05 Hardware-only caveat` section that:

- States explicitly that the milestone close is gated on the
  CI/dry-run proof (QA-01, QA-02) plus the
  hardware-independent live evidence (QA-03 repo/helper sync).
- Lists every QA-04 item that could not be executed on this
  dev machine and the exact hardware or install step needed.
- Notes that the live-evidence document must be re-run on a
  real-hardware machine before a *production* release of v0.3,
  but that the dev-environment CI proof is sufficient for the
  milestone archive.

## Success criteria

- `12-LIVE-VERIFICATION.md` exists.
- It captures the build-ID sync between repo daemon, embedded
  helper, and the dry-run shm check.
- It lists the QA-04 operator evidence with a `[x]` or
  `[ ] BLOCKED:` state for every item.
- The QA-05 caveat makes clear which evidence is CI-only and
  which is hardware-blocked.

## Output

A single `docs(12):` commit adding
`12-LIVE-VERIFICATION.md` (and the captured log if the plan
generates one).
