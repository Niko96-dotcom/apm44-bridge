# Plan 10-02: Metrics seqlock stress + publication-contract assertion

## Objective

Prove (rather than assume) that the C++ `MetricsSnapshot` publication
mechanism is data-race-free. Add a multi-threaded stress test that
exercises `publishMetricsSnapshot` (writer) and `readMetricsSnapshot`
(reader) concurrently, and add a static / source-level assertion that
no path in the codebase copies a plain `MetricsSnapshot` across
threads without going through the seqlock.

## Tasks

### Task 1: Refactor the seqlock pair for direct testability

**Type:** auto
**Files:** `BridgeDaemon/src/engine/BridgeEngine.h`,
`BridgeDaemon/src/engine/BridgeEngine.cpp`

The seqlock pair (`publishMetricsSnapshot` and `readMetricsSnapshot`)
is currently a private member of `BridgeEngine`. To test it without
spinning up a full `BridgeEngine` (which needs Core Audio device
IDs and a prepared ring), extract the publication primitives into a
free function pair in the `apm44` namespace inside a new header
`BridgeDaemon/src/engine/MetricsPublisher.h` (and a corresponding
`.cpp` if needed). Keep the existing
`BridgeEngine::publishMetricsSnapshot` / `readMetricsSnapshot` as
thin shims that delegate to the new free functions, so the public
API of `BridgeEngine` is unchanged.

```cpp
namespace apm44 {

struct MetricsPublisherState {
  std::atomic<uint32_t> seq{0};
  MetricsSnapshot snapshot{};
};

void PublishMetrics(MetricsPublisherState& state,
                    const MetricsSnapshot& next);
MetricsSnapshot ReadMetrics(const MetricsPublisherState& state);

}
```

This makes the publication contract independently testable. The
existing `BridgeEngine::metricsSeq_` and `metricsSnapshot_` fields
become an inline `MetricsPublisherState publisher_;` (or stay as
separate fields; the free functions take a `MetricsPublisherState&`
either way).

### Task 2: Multi-threaded seqlock stress test

**Type:** auto
**Files:** `tests/test_bridge_metrics_json.cpp` (or new
`tests/test_metrics_publication.cpp`)

Add a Catch2 test that:

1. Constructs a `MetricsPublisherState` on the stack.
2. Spawns one writer thread that calls `PublishMetrics` in a tight
   loop, each iteration increasing `underruns`, `overruns`, and
   `xruns` by small increments and varying `fillMs`.
3. Spawns 4 reader threads that each call `ReadMetrics` in a tight
   loop, accumulating `underruns`, `overruns`, `xruns` observed.
4. Runs for ~50,000 iterations per thread (or 1 second, whichever
   is shorter).
5. Joins all threads.
6. Asserts:
   - No reader ever observed a `underruns` value that was LESS than
     the highest value any other reader observed (monotonic
     publication — readers cannot see values regress because the
     writer only ever increments).
   - The maximum `underruns + overruns + xruns` observed by all
     readers is non-decreasing over wall-clock time.
   - The final writer iteration's value is exactly equal to the
     maximum observed by any reader (the writer's last write must
     be visible eventually).

These invariants are guaranteed by the seqlock: if a reader
observes a torn value, the seqlock retry loop kicks in and
re-reads; the stress test would observe non-monotonic counts only
if a reader bypassed the seqlock — which is exactly the bug
METR-03 is meant to prevent.

### Task 3: Source-level assertion that no path copies MetricsSnapshot
without the seqlock

**Type:** auto
**Files:** `tests/test_bridge_metrics_json.cpp` (or a new
`tests/test_metrics_contract.cpp`)

Add a test or static-check helper that greps the source tree at
test time and asserts that any read of `MetricsSnapshot` in the
`BridgeDaemon/src` tree is preceded by a call to `ReadMetrics` or
`publishMetricsSnapshot`. The simplest way: parse the `.cpp` and
`.h` files in `BridgeDaemon/src` for any line that mentions
`MetricsSnapshot` and check that the surrounding 5 lines include
either the publish or read free function name. If a future change
adds a bare copy, the test fails.

The check is intentionally simple (text-based) — it is a regression
guard, not a full static analyzer.

### Task 4: Verify metrics fields remain available to CLI JSON + UI

**Type:** auto
**Files:** (none modified)

Confirm the existing `test_bridge_metrics_json` cases still pass
after the refactor. The fields exposed (`fillMs`, `smoothedRatio`,
`ppm`, `underruns`, `overruns`, `xruns`) must all be present in
the JSON output and match the values returned by `ReadMetrics`.

### Task 5: Build and run

**Type:** auto
**Files:** (none modified)

Build all targets, run ctest, confirm all metrics tests pass and
no other test regresses.

## Success Criteria

- `MetricsPublisher` free functions exist and the seqlock
  invariants are exercised in a multi-threaded test.
- The stress test runs for at least 50k iterations per thread
  without any reader observing a non-monotonic count.
- No source file in `BridgeDaemon/src` copies a bare
  `MetricsSnapshot` outside the seqlock pair (regression guard).
- `test_bridge_metrics_json` still passes (METR-02).
