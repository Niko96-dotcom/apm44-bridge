# Plan 10-01: Concurrent termination waiters and SIGKILL escalation

## Objective

Make the Swift termination-wait path safe under concurrent callers and
prove the SIGKILL escalation behaves correctly when the daemon ignores
SIGTERM. Replaces the single `terminationContinuation` slot with an
array of continuations and adds Swift tests that cover timeout,
escalation, and concurrent waiters.

## Tasks

### Task 1: Replace single continuation with a waiter list

**Type:** auto
**Files:** `App/APM44Bridge/BridgeProcessManager.swift`

In `BridgeProcessManager`:

1. Replace the single field
   ```swift
   private var terminationContinuation: CheckedContinuation<Void, Never>?
   ```
   with a list:
   ```swift
   private var terminationContinuations: [CheckedContinuation<Void, Never>] = []
   ```
2. In `waitForTermination` (lines 401-421), when we are about to
   suspend, append the new continuation to
   `terminationContinuations` instead of assigning to a single slot.
   The existing fast-path "if state == .idle, process == nil then
   resume immediately" still works.
3. In `resumeTerminationWaiters()` (lines 604-607), resume all
   continuations currently in the list and then clear the array:
   ```swift
   let pending = terminationContinuations
   terminationContinuations = []
   for c in pending { c.resume() }
   ```
4. Keep the helper on the main actor (the whole class is
   `@MainActor`, so no extra isolation is needed).

### Task 2: Bound the post-SIGKILL wait and force a final result

**Type:** auto
**Files:** `App/APM44Bridge/BridgeProcessManager.swift`

In `finishStopWithEscalation` (lines 561-581), the second
`waitForTermination(timeout: .seconds(5))` already has a bound. The
existing structure is:

```swift
do {
  try await waitForTermination(timeout: .seconds(5))
  return true
} catch {
  // escalate to SIGKILL
  kill(proc.processIdentifier, SIGKILL)
}
do {
  try await waitForTermination(timeout: .seconds(5))
  return true
} catch {
  clearPipeHandlers()
  return false
}
```

The current behaviour is correct in shape but has one gap: if the
daemon survives both waits, the helper returns `false` but never
explicitly resumes any continuations that were registered between
the two `waitForTermination` calls. Tighten the second `catch` to
also call `resumeTerminationWaiters()` before returning, so the
caller's await unblocks deterministically.

```swift
} catch {
  clearPipeHandlers()
  resumeTerminationWaiters()
  return false
}
```

Also add a one-line comment noting that the helper always returns a
final value (`true` or `false`) — never hangs.

### Task 3: Add Swift tests for the new contract

**Type:** auto
**Files:** `tests/test_bridge_process_manager.swift`

Extend the existing fixture with three new cases:

1. **`ConcurrentTerminationWaitersAllComplete`** — start the manager
   with a fake process, kick off two `await waitForTermination`
   tasks in parallel, simulate the daemon terminating, and assert
   that BOTH tasks complete (no overwrite, no hang). Verify
   `terminationContinuations` is empty after the resumes.
2. **`DaemonIgnoringTerminationEscalatesToSigkill`** — use the
   `ProcessLaunching` mock to start a child that ignores SIGTERM
   and exits on SIGKILL; assert that the helper returns `true`
   after a single escalation (i.e., the post-kill wait resolved).
3. **`TerminationWaiterUnblocksWhenStateTransitionsToIdle`** —
   register a waiter while the manager is in `.running` state,
   force a `transitionToIdle()` (exposed via a test-only hook or
   via `handleTermination(proc)`), and assert the awaiter
   completes.

These tests use a mock `ProcessLaunching` so no real `apm44-bridge`
binary is needed (matches the existing test style in this file).

## Success Criteria

- `terminationContinuations` is an array, not a single optional.
- `waitForTermination` appends; `resumeTerminationWaiters` drains
  and clears the array.
- After SIGKILL timeout, the helper calls
  `resumeTerminationWaiters()` so any in-flight awaiter unblocks
  with a final `false` result rather than hanging.
- Concurrent-waiter Swift test passes.
- Daemon-ignoring-termination test passes (escalates to SIGKILL).
- State-transition unblocks waiter test passes.
