<interfaces>
The shipped overrun policy is drop-new-input: the input realtime producer may push and record an overrun, but it must not pop consumer-owned frames.

Core Audio callback constraints:
- No allocation, locks, logging, or blocking work inside IOProc callbacks.
- Non-interleaved channel buffers can have different `mDataByteSize` values; processed frames must not overread either buffer.
- Virtual-device mode has no input IOProc. Cleanup after output-start failure must not stop a null input IOProc.
</interfaces>
</context>
