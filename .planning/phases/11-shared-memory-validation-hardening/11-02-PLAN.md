# Plan 11-02: Bounded diagnostics and corrupt-shm regression tests

## Objective

Replace the unbounded build-ID rendering in `DescribeHeaderMismatch`
with explicit bounded copy + `strnlen`, and add a Catch2 test file
that exercises truncated, header-only, huge-capacity, and
unterminated build-ID cases against isolated shm names
(PID-suffixed, never `/apm44_bridge_ring`).

## Tasks

### Task 1: Bounded build-ID rendering in `DescribeHeaderMismatch`

**Type:** auto
**Files:** `Shared/src/MmapShmRing.cpp`

Replace the current direct `<<` of `header.producer_build_id` and
`kBuildId` with a helper that:

1. Copies the field into a local buffer of size
   `kShmBuildIdBytes + 1` (zero-initialised).
2. Uses `strnlen` on the original field, bounded by
   `kShmBuildIdBytes`, to find the real length.
3. Constructs a `std::string` of exactly that length.
4. If the length is zero, substitutes `"<unterminated>"` as the
   rendered value (this is a sentinel, not a real build ID).
5. Streams the bounded string into the diagnostic.

Apply the same pattern to the `kBuildId` consumer-side rendering
(it is a string literal so the size is known at compile time, but
the helper keeps the diagnostic code uniform and prevents
accidental regressions if a non-literal source is ever substituted).

### Task 2: New test file `test_mmap_shm_validation.cpp`

**Type:** auto
**Files:** `tests/test_mmap_shm_validation.cpp`,
`tests/CMakeLists.txt`

Create a Catch2 test file with the following cases, all using
isolated shm names (`/apm44_validation_<pid>_<idx>`):

1. **`OpenRejectsTruncatedObject`** — create a 32-byte shm
   object (less than `sizeof(ShmRingHeader)`), then attempt
   `MmapShmRing::open(Consumer)`. Assert `lastErrorCode ==
   HeaderTruncated` and `lastError()` mentions the truncated
   size.
2. **`OpenRejectsValidHeaderWithHugeCapacity`** — create a
   shm object at `ShmTotalSize(64)` size, write a valid
   `ShmRingHeader` (correct magic, version, channels) but
   declare `capacity_frames = 1_000_000`. Open and assert
   `lastErrorCode == CapacityExceedsObject` and the message
   contains both the mapped size and the declared total.
3. **`HeaderMismatchDiagnosticHandlesUnterminatedBuildId`** —
   create a shm object of `ShmTotalSize(64)` size. Write a
   header with magic, version, channels, etc. all valid, but
   set the `producer_build_id` field to all `'X'` (64 bytes,
   no null). Then call `MmapShmRing::open` with role Consumer
   and a consumer whose build ID is shorter than 64 chars.
   Assert the `lastError()` string either:
   - Stops at the embedded null and never reads past 64 bytes
     (verifiable by checking the diagnostic does not include
     arbitrary header bytes past the build-ID field), or
   - Substitutes the `<unterminated>` marker.
4. **`OpenAcceptsCorrectlySizedObject`** — sanity baseline.
   Create a properly sized shm object, open, push, pop. All
   operations succeed. This guards against the validation
   being too strict.
5. **`LiveSizeChangeTriggersStale`** — open an object, capture
   the identity, then `ftruncate` the same fd to a different
   size and re-`fstat`. Assert `isMappedObjectStale() == true`
   (SHM-03).

Wire the new test file into `tests/CMakeLists.txt` via
`apm44_add_test(test_mmap_shm_validation test_mmap_shm_validation.cpp)`.

Each test cleans up its shm name with `::shm_unlink` in a
`REQUIRE` or in a destructor-equivalent Catch2 `DYNAMIC_SECTION`
cleanup helper so a failure does not leak shm names.

### Task 3: Build and run
