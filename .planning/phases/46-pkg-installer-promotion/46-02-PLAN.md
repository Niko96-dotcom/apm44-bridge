<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| signed package -> Apple notary service | Local package bytes are submitted to Apple and must receive Accepted status. |
| stapled package -> public release gate | The package becomes eligible for wrapping or publication only after local validation passes. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-46-04 | Tampering | `scripts/notarize-release-pkg.sh` checksum generation | mitigate | Generate `.pkg.sha256` only after stapling, final signature validation, and Gatekeeper assessment. |
| T-46-05 | Spoofing | package signature validation | mitigate | Require `pkgutil --check-signature` output to contain `Developer ID Installer` before and after stapling. |
| T-46-06 | Repudiation | notary result handling | mitigate | Continue using `require_notary_accepted` so non-Accepted status and submit failures fetch notary logs and fail closed. |
| T-46-07 | Denial of Service | Gatekeeper package rejection | mitigate | `spctl --assess --type install --verbose=4 "$PKG"` blocks release flow before later phases consume the package. |
</threat_model>
